Payments — wireframe

Low-fi, but built from the live tokens and the existing SignupWizard card (max-w-md rounded-2xl bg-paper p-6). Steps stay login → name → pay → keys. Only the name step's price row and the pay step body change; both live in nail's lib/payments module. Red pins 1 mark what is new versus today's UI.

1 · Name step — price row

Same tier card. Open builds show both prices; store builds show only the store's localized price — no sats anywhere.

2 · Pay step — web & direct APK

The title ("One payment, and it's yours") and "Claiming alice@…" subtitle are unchanged. The body gains a method picker; Lightning is today's InvoiceQR, moved into the package untouched.

3 · Pay step — store builds

No picker, no Lightning, no Stripe. One button that opens the native payment sheet.

4 · Shared states (all rails)

After any rail reports done, the wizard waits for the backend to say "paid" — never for the client's own belief. Card and store both use GET /api/orders/:key/status; Lightning keeps its WebSocket.

Notes

Pins — 1 fiat price as secondary line (open builds only) · 2 CTA no longer names a method · 3 store-localized price · 4 Stripe-hosted iframe — we style only the surrounding card · 5 APK hosted-checkout hand-off · 6 App Review requirement.

Dark mode / in-app modal — the buy flow inside the mail client renders under .landing (BuyAddressModal), which pins the light palette, so this wireframe's single light theme is correct for both surfaces.
Accessibility — the picker is a role="radiogroup" with arrow-key navigation, matching the tier cards' role="radio" pattern; the Android back button closes the sheet via the existing back stack (no new overlay).
